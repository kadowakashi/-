# さけいちず

現在のバージョン: v1.6

## アプリ名の由来

「さけいちず」は、飲んだお酒や訪れたお店を地図上に記録するためのローカルWebアプリです。
名前には「さけ＋位置＋地図」と「さけ＋一途」の意味を込めています。

## アプリ概要

日々の飲み会、飲み歩き、居酒屋巡り、地酒レビューを「地図＋日記」として残せます。
HTML / CSS / JavaScriptだけで動作し、地図はLeaflet + OpenStreetMap、データ保存はブラウザのlocalStorageを使います。
ログイン、クラウド保存、スマホアプリ化、AI機能は未実装です。

## 使い方

1. `index.html` をブラウザで開きます。
2. 飲み会の日付、タイトル、同行者、メモ、タグを入力して保存します。
3. 地図をクリックして、店・スポットを追加します。
4. 店名、カテゴリ、飲み物カウント、飲んだものメモ、この店の一品！、評価、酒ログ、写真などを入力します。
5. 翌日以降に飲み会記録を編集し、翌日の体調や体調メモを追記できます。
6. 登録済み記録、検索、集計、写真一覧で振り返ります。
7. 大きな操作の前には、通常JSONエクスポートでバックアップします。

## スマホで飲み会中に使う場合

1. 先に飲み会記録だけ作成しておきます。
2. 店に着いたら地図のすぐ上にある「現在地を表示」を押すか、地図をタップします。
3. 「現在地を表示」を押すと地図までスクロールし、位置情報の許可後に現在地中心へ移動します。
4. v1.6以降、スポット追加画面は詳細入力が初期表示です。急いで残したいときは「簡易入力」へ切り替えます。
5. 地図をタップすると、OpenStreetMap系のNominatimから候補名と住所を取得し、必要に応じて店名へ反映できます。
6. 候補は古い・不正確な場合があるため、フォーム内の「Googleマップで店舗確認」ボタンで店名を確認してから入力できます。
7. 簡易入力では、店名、飲み物カウント、銘柄、写真、一言メモ、評価だけで保存できます。
8. 水、ビール、日本酒、ハイボールなどは＋/−ボタンで杯数を記録できます。
9. 写真は1スポット3枚まで、圧縮してlocalStorageに保存されます。

## 入力途中の下書き保存

- v1.6以降、飲み会記録フォームとスポット追加・編集フォームの入力途中データを、正式保存とは別の下書きとしてlocalStorageに一時保存します。
- 下書きキーは `sakeichizu.sessionDraft.v1.6` と `sakeichizu.spotDraft.v1.6` です。正式記録キー `nomichizu.records.v0.1` とは分けています。
- 入力変更後、短い待機時間を置いて自動保存します。
- 再表示時に下書きがある場合は、復元するか破棄するか確認します。
- 飲み会やスポットを正式保存すると、対応する下書きは削除されます。
- 写真Base64本体は容量が大きいため、スポット下書きには含めません。写真キャプションなど軽い情報だけを対象にします。

## バックアップ方法

- 通常JSONエクスポートは、写真データと写真キャプションを含む完全バックアップです。
- 写真なしJSONエクスポートは、写真本体を除外した軽量バックアップです。
- 別ブラウザや別PCへ写真も含めて移したい場合は、通常JSONを使ってください。
- 写真が増えてlocalStorage容量が大きくなる前に、定期的な通常JSONバックアップをおすすめします。

## GitHub Pages公開時の注意

- GitHubへアップロードするのは、基本的に `index.html`、`style.css`、`app.js`、`README.md` の4ファイルだけにしてください。
- 通常JSON、写真なしJSON、CSV、写真ファイル、スクリーンショット、バックアップZIPなど、個人の飲み会記録や写真を含むファイルはGitHubへアップロードしないでください。
- 通常JSONには写真Base64本体が含まれる場合があります。公開リポジトリへ入れると個人データが公開されます。
- CSVには写真本体は含まれませんが、店名、日付、メモ、銘柄、エリアなどの個人記録が含まれるため、公開しないでください。

## 写真保存の注意

- 写真は1スポットにつき最大3枚です。
- jpg / jpeg / png / webp を選択できます。
- 画像はブラウザ上で長辺最大1280px、JPEG品質0.72程度に圧縮し、Base64 Data URLとしてlocalStorageに保存します。
- 元画像をそのまま保存するわけではありません。
- localStorageにはブラウザごとの容量上限があります。写真を多く保存すると、保存容量を超える場合があります。
- 写真整理の前や全写真一括削除の前には、通常JSONで写真付きバックアップを作成してください。

## JSONと写真なしJSON

- 通常JSON: 飲み会、スポット、酒ログ、位置情報、写真、キャプションを含みます。
- 写真なしJSON: 各スポットの `photos` を空配列にした軽量データです。
- 写真なしJSONから復元しても、写真本体は戻りません。

## CSVエクスポートとCSVインポート

- 通常CSVは、1行を1スポットとして飲み会情報とスポット情報をまとめて出力します。
- CSVはExcelで開きやすいUTF-8 BOM付きです。
- カンマ、改行、ダブルクォートを含む文字列はCSVエスケープします。
- v1.5以降、Excelで数式として解釈されやすい `=`、`+`、`-`、`@` で始まる文字列セルは、先頭にアポストロフィを付けて出力します。
- CSVには画像Base64本体を含めません。写真枚数、写真あり、写真キャプション、保存写真サイズ目安を出力します。
- CSVには、支払額合計、住所、地図候補名、Googleマップ確認用URL、飲み物カウント、合計杯数も出力します。
- 通常CSVの料理欄は「この店の一品！」として出力します。旧CSVの「食べたもの」列もインポートできます。
- 評価列はS/A/B/C/Dで出力します。旧CSVの1〜5評価もインポート時にS/A/B/C/Dへ変換します。
- CSVインポートは、さけいちずの通常CSVエクスポート形式を追加取り込みします。
- CSVインポートで住所列や飲み物カウント列があれば取り込みます。ない場合は空欄または空配列として扱います。
- CSVインポートでは写真本体は復元されず、`photos` は空配列になります。
- CSVインポート時、数式注入対策で付いた先頭アポストロフィは可能な範囲で自然に読み込みます。
- CSVインポート前には、通常JSONエクスポートでバックアップすることをおすすめします。

## エリア管理

- v1.3以降、エリアはスポット項目ではなく、飲み会タグで管理します。
- 地域タグの例は、秋田駅前、川反、大町、山王、土崎、能代、仙台、東京、旅行先です。
- 既存データに含まれるスポットの `area` は読み込み、検索、CSV/JSON互換、エリア別集計で引き続き扱います。
- 新規スポット追加時はエリア入力を求めません。
- エリア別集計は、既存スポット `area` があればそれを優先し、なければ飲み会タグ内の地域タグを使います。
- エリア統合では、表記ゆれを指定したエリア名に置き換えます。
- エリア統合では、飲み会、スポット、写真、酒ログ、位置情報は削除しません。

## データチェック

- データチェックは、localStorage内の記録形式を確認します。
- 飲み会ID、スポットID、緯度経度、photos形式、酒ログ項目、エリア項目、住所・地図候補項目、飲み物カウント、評価を確認します。
- 支払額が数字として読み取れない場合は警告として表示します。エラー扱いにはしません。
- 自動補正では、不足ID、旧形式写真、photos空配列、酒ログ項目、エリア項目、住所・地図候補項目、飲み物カウントなどを補完します。
- 緯度経度が数値として扱えないデータは、安全のため自動補正しません。
- 重複候補チェックは、日付、飲み会タイトル、店名、緯度経度の近さ、銘柄名を使った簡易判定です。自動削除はしません。

## 金額集計について

飲み会ごとの支払額合計は、各スポットの「支払額」に含まれる数字から自動計算します。
「3000」「3,000」「3000円」「約3000円」などは可能な範囲で読み取ります。
総額は各スポットの支払額から自動計算されるため、総額メモは通常入力不要です。
旧データに総額メモが残っている場合も読み込み可能ですが、通常画面では主項目として表示しません。
月別集計の金額も、スポット支払額からの概算です。自由入力からの推定なので、正確な会計処理ではありません。

## タグの使い方

- よく使うタグはチェックボックスから選べます。
- 一人飲み、友人、職場、旅行、秋田駅前、川反、日本酒、ビールなどの初期候補があります。
- 自由タグ欄では、カンマ、スペース、改行区切りで好きなタグを追加できます。
- 「タグ設定」ボタンから、チェックボックスに表示する候補タグを追加、削除、並び替えできます。
- タグ候補は `sakeichizu.tagSettings.v1.4` に保存され、再読み込み後も維持されます。
- タグ候補を削除しても、過去の飲み会記録についているタグ自体は削除されません。
- 保存された自由タグは、次回以降の候補にも追加されます。
- 「記録中のタグを候補に追加」ボタンで、既存データ内のタグを候補に戻せます。
- タグは検索、ブログ下書き、CSV、JSONに反映されます。

## 翌日の体調記録

- 飲み会記録ごとに、翌日の体調を複数選択できます。
- 初期候補は、快調、普通、二日酔い、頭痛、吐き気、胃もたれ、眠気、だるさ、記憶あいまい、水分不足感です。
- 体調メモには、翌朝の状態や水分補給、睡眠などの振り返りを自由に書けます。
- 空欄でも保存できます。飲み会翌日以降に編集して追記する使い方を想定しています。
- 体調記録は、飲み会一覧、選択中の飲み会情報、ブログ下書き、通常CSV、JSON、検索、集計に反映されます。
- 飲酒をすすめるためではなく、体調管理と振り返りのための記録として使ってください。

## 店舗名・住所候補について

- 地図クリック時に、Nominatimの逆ジオコーディングAPIで候補名と住所を取得します。
- v1.5以降、候補取得は短い待機時間を置いてから行い、連続タップ時は最後の地点だけ問い合わせます。
- 近い地点の候補はブラウザ内キャッシュを使い、不要な連続リクエストを抑えます。
- Google Places APIは使用していません。
- 候補はOpenStreetMap/Nominatim由来のため、古い・不正確な場合があります。自動確定ではなく補助表示です。
- 候補を店名欄に反映するボタンで入力補助として使えます。
- スポット追加フォーム内の「Googleマップで店舗確認」ボタンから、クリック地点を外部のGoogleマップで確認できます。
- 通信失敗時や候補がない場合も、従来どおり手入力できます。
- Googleマップ確認リンクは、保存済みURLを信用せず緯度・経度から毎回生成します。

## スポットの位置情報

- 緯度・経度は地図クリック時に内部保存されます。
- 通常のスポット追加・編集画面では、緯度・経度の直接入力欄は表示しません。
- ピン表示、ルート線、Googleマップ確認URL、JSON/CSV出力には、内部保存された緯度・経度を引き続き使います。

## この店の一品！と評価

- 「この店の一品！」は、その店で一番おいしかった料理を1つだけ残す欄です。
- 旧データや旧CSVの「食べたもの」は、「この店の一品！」として読み込み、表示します。
- スポット評価はS/A/B/C/Dで記録します。
- S：最高。必ずまた行きたい
- A：かなり良い。また行きたい
- B：普通に良い
- C：やや物足りない
- D：再訪はしなくてよい
- 旧データの数値評価は、5→S、4→A、3→B、2→C、1→Dとして読み込みます。
- 月別集計やエリア別集計の平均評価は、S=5、A=4、B=3、C=2、D=1として内部計算し、「A相当 (4.0)」のように表示します。

## 飲み物カウントについて

- 水、ビール、日本酒、焼酎、ワイン、ウイスキー、ハイボール、カクテル、サワー、ソフトドリンク、その他を＋/−で記録できます。
- 0杯の項目は保存対象から外れます。
- 飲み物カウントは「何を何杯飲んだか」を記録する欄です。
- 既存の自由記載欄は「飲んだものメモ」として残しています。
- 飲んだものメモは、飲み比べセット、店員さんおすすめ、乾杯ビールだけ、水も多めに飲んだ、など杯数だけで表しにくい補足に使います。
- 酒ログは、銘柄、味の印象、おすすめ度、もう一度飲みたいかなど、印象に残ったお酒のレビューに使います。
- CSVには「飲み物カウント」と「合計杯数」を出力します。
- 酒ログ集計と月別集計にも、飲み物種類別の合計杯数や月別合計杯数を表示します。
- 飲酒量を競わせるランキングや称号はありません。自分用の振り返り記録として使います。

## 既存データとの互換性

- 記録データのlocalStorageキーは `nomichizu.records.v0.1` を維持しています。
- 表示設定キーは `sakeichizu.displaySettings.v0.4` を維持しています。
- 下書き保存キーは `sakeichizu.sessionDraft.v1.6` と `sakeichizu.spotDraft.v1.6` です。正式保存データとは分離しています。
- フォルダ名は変更していません。
- 酒ログ、エリア、写真、キャプションがない既存データでも、空欄または空配列として扱います。
- 翌日の体調項目がない既存データでも、空欄または空配列として扱います。
- 住所、地図候補名、Googleマップ確認用URL、飲み物カウントがない既存データでも、空欄または空配列として扱います。
- 既存のスポット `area`、総額メモ、文字列形式タグ、`drinkCounts`、旧数値評価は壊さず読み込みます。
- 既存の `foods`、`food`、`eatenItems` は「この店の一品！」として扱います。
- 旧形式の写真配列 `photos: ["data:image..."]` も読み込めます。

## 既知の制限

- データはブラウザのlocalStorageに保存されます。ブラウザ変更、履歴削除、端末故障には備えられません。
- 写真を大量に保存するとlocalStorage容量を超える場合があります。
- CSVインポートでは写真本体を復元できません。
- 店舗名・住所候補はNominatim由来のため、店名が取れない、住所が粗い、実際の店舗とずれる場合があります。
- 下書き保存は同じブラウザ内のlocalStorageに限られます。端末変更やブラウザ変更では引き継がれません。
- スポット下書きには写真本体を含めません。写真は正式保存後にバックアップしてください。
- 支払額合計はスポット支払額内の数字からの概算です。
- 重複候補チェックは簡易判定で、誤検出や見逃しがあります。
- クラウド同期、ログイン、スマホアプリ化、写真の外部ファイル保存は未実装です。
